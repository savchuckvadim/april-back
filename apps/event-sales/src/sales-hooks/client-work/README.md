# «Работа клиента» (client-work)

Блок в «Звонках» (фронт: `apps/event-sales/modules/features/ClientWork`):
все **открытые сделки клиента** в воронке «ОП Основная» и присоединение
выбранных к основной — одной кнопкой, только руководителю.

Зачем: «Возможные пересечения» сделки **той же компании** не показывают —
source graph кладёт их в «окружение» (`excluded`), это не дубль. А почти все
дубли из еженедельного отчёта (`duplicate-report`) — именно такие. Без этого
блока руководитель не мог выполнить задачу отчёта.

## Ручки

```
POST /sales-hooks/client-work/deals {domain, dealId, userId}
POST /sales-hooks/client-work/join  {domain, initiatorUserId, mainDealId, dealIds[], operationId?}
```

- `deals` — клиент сделки (компания, без неё — контакт; сделка без компании
  с контактом единственной компании — к этой компании) и его открытые
  сделки с тем же разбором, что у отчёта: предложенная основная, самая
  свежая, «ведёт сам», заметки (два менеджера, разные ИНН), «как вели».
  `canJoin` — проверено на сервере.
- `join` — 403 не руководителю; выбор перепроверяется **свежим** чтением
  клиента основной (400 «уже закрыты — обновите список»); дальше одна
  операция хука `join-to-main` на всю пачку (бережно: дубль → «Дубль»,
  задачи/дела/контакты/заявки → в основную, ничего не удаляется). Статус —
  `GET /sales-hooks/operations/{operationId}`.

## Права (`shared/head-access`)

Руководитель = суперпользователь вендора, глава любого уровня по структуре
(группа, ОП, «Главы»), или видимость шире своей из настроек «Отдел продаж».
Сбой структуры — отказ (fail closed), суперпользователь проходит всегда.
Та же проверка теперь стоит на `join-to-main/run` («Присоединить сюда») и
`merge-duplicates/run` («Объединить карточки компаний»).

| `services/client-work.service.ts` | список, права, постановка операции |
| `dto/client-work.dto.ts` | запросы и ответ |

создаётся `new` на запрос (CLAUDE.md).
