# Хук «лид → работа» (`lead-to-work`)

Один хук на все сценарии «взять лид в работу отдела продаж». Что именно
произойдёт — определяют флаги; сам алгоритм один и тот же.

Главное отличие от старого ХО-хука: этот **не обнуляет** работу. Он
достраивает граф связей, а не сбрасывает клиента в начало воронки.

---

## 1. Три режима использования (одним хуком)

### Режим A. «Перевод в работу» — переезд лида на сделку

Заявка обработана, менеджер начинает вести клиента в воронке ОП.

```
stageMode=from_lead, isXo=N, taskMode=move
```

Что делает: создаёт основную сделку ОП (стадия — зеркало стадии лида, см.
§3), связывает её с лидом, переносит открытые задачи с префиксом «Звонок»,
двигает статус лида. ХО-сделку НЕ создаёт, ничего не закрывает.

### Режим B. «Холодный обзвон по заявке» — новый ХО из лида

Лид холодный, нужен цикл обзвона с аналитической ХО-сделкой.

```
stageMode=cold, isXo=Y, taskMode=close
```

Что делает: создаёт основную сделку ОП в стадии «Холодная» + ХО-сделку,
закрывает старые задачи и ставит новую «Холодный обзвон …».
**Отличие от классического ХО-хука:** смежные сделки компании не
закрываются, компания не обнуляется — прошлое сохраняется.

### Режим C. «Взять в работу с созданием компании»

У лида компании нет, но работать нужно от компании.

```
createCompany=Y (+ любой stageMode)
```

Что делает: создаёт компанию с названием лида, привязывает к ней сделку,
ставит лиду «Установлена компания». Без флага сделка спокойно живёт **без
компании** — это штатный сценарий, фейковые компании не создаём.

> Компания из лида всегда важнее флага: если она у лида есть — берём её и
> новую не создаём, что бы ни стояло в `createCompany`.

## 2. Флаги

| Флаг | Значения | По умолчанию | Влияние |
|---|---|---|---|
| `stageMode` | `from_lead` \| `cold` | `from_lead` | стадия создаваемой сделки ОП |
| `isXo` | `Y` \| `N` | `N` | создавать ли ХО-сделку; при `Y` задачи закрываются, новая называется «Холодный обзвон …» |
| `createCompany` | `Y` \| `N` | `N` | создавать ли компанию, если её нет у лида |
| `taskMode` | `move` \| `close` | `move` | перенести открытые задачи или закрыть и поставить новую |
| `deadline` | `DD.MM.YYYY HH:mm:ss` | — | дедлайн новой задачи (локаль портала) |
| `name` | строка | название лида | название события в задаче |

`responsible` в вебхуке приходит как `user_123` (формат робота), в `/run` —
числом. См. предупреждение в DTO: тип query-поля обязан быть `string`.

## 3. Движение стадий: что двигается, а что нет

### 3.1 Стадия создаваемой СДЕЛКИ ОП

| Условие | Стадия сделки |
|---|---|
| `stageMode=cold` | `sales_cold` («Холодная») |
| `stageMode=from_lead`, у стадии лида есть зеркало | зеркальная стадия воронки (`lead_pres` → `sales_pres`) |
| `stageMode=from_lead`, зеркала нет | `sales_warm` («Переговоры») + warning |
| стадия не сопоставлена на портале | дефолтная стадия воронки + warning (не ошибка) |
| воронки ОП нет на портале | ❌ ошибка — работать негде |

### 3.2 Статус ЛИДА

| Ситуация | Что происходит со статусом лида |
|---|---|
| Лид сконвертирован штатно (CONVERTED) | **не трогаем** — Битрикс считает лид закрытым; пишем только поля и историю |
| `stageMode=from_lead` и стадия лида зеркальна стадии ОП | **остаётся на месте** — лид и сделка идут «параллельно» на одном этапе |
| У лида есть компания | → «Работа с компанией» (`lead_company_work`) |
| Компании нет | → «Взята в работу» (`lead_taken_in_work`) |
| Нужная стадия не установлена/не сопоставлена | статус не меняется + warning |

Дополнительно всегда проставляется `op_lead_status`: «Работа с компанией»
или «Работа со сделкой» — это наш собственный статус, он не зависит от
стадий Битрикса и работает даже без сопоставления стадий.

**Принцип:** любое подмножество сопоставленных стадий рабочее. Нет стадии —
шаг пропускается с warning, операция доходит до конца.

## 4. Какие связи записывает хук

| Где | Поле | Значение |
|---|---|---|
| Сделка | `deal_from_lead_id` | `L_{leadId}` — лид-первоисточник (без конвертации Битрикса) |
| Сделка | `deal_joined_leads` (multiple) | union со старым значением: все присоединённые лиды |
| Лид | `to_base_sales` | ссылка на основную сделку (`D_{id}`) |
| Лид | `to_xo_sales` | ссылка на ХО-сделку (при `isXo=Y`) |
| Лид | `op_lead_is_company` | 1, если компания есть/создана |
| Задача | `UF_CRM_TASK` | union: лид + сделка (+ компания, + ХО-сделка) |

Неустановленное поле пропускается молча — граф достроится, когда поле
поставят (см. `SALES_HOOKS_GUIDE.md`, раздел установки).

---

## 5. Идемпотентность

Перед записью хук читает состояние портала. Если у лида уже есть наша
сделка (`to_base_sales`), включается режим **reuse**: вторая сделка не
создаётся, связи доводятся, `deal_joined_leads` дополняется. Поэтому:

- повторный клик кнопки безопасен;
- робот, стрельнувший пять раз, даст одну операцию (окно тишины 1.5 с);
- «Преобразовать в работу» на фронте не показываем, если связка уже есть —
  это дубль по смыслу, даже если технически безопасен.

---

## 6. Что хук НЕ делает

- не пишет KPI и списки (прошлое не переписываем);
- не закрывает смежные сделки компании (в отличие от классического ХО);
- не двигает статус конвертированного лида;
- не создаёт компанию без явного флага;
- не трогает чужие воронки.
