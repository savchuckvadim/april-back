# Картинки поставщика (`provider-image`)

Печать, подписи и логотип поставщика для документов Конструктора. Картинка принадлежит
реквизитам (`rqs`): юридическому лицу, от имени которого выставляется КП.

## Таблица `provider_images`

Миграция: `online/database/migrations/2026_11_23_120000_create_provider_images_table.php`
(применяет владелец; Prisma-схема правится руками, `db pull` запрещён).

| Поле | Что хранит |
|---|---|
| `id` | uuid, его выдаёт Nest; он же имя файла на диске |
| `rq_id` | реквизиты (`rqs.id`), внешний ключ с каскадом |
| `role` | `stamp`, `signature_director`, `signature_accountant`, `logo` |
| `path` | путь внутри `storage/app`: `konstructor/provider-images/{rqId}/{id}.{ext}` |
| `format`, `width`, `height`, `size` | что Nest определил по файлу: png или jpg, пиксели, байты |
| `original_name` | имя файла при загрузке, только для показа в админке |
| `legacy_file_id` | запись `files`, из которой картинка перенесена (временный перенос, повторный запуск копий не плодит) |

На реквизиты приходится одна картинка каждой роли: `(rq_id, role)` уникальна. Перечень ролей
живёт в коде (`provider-image.role.ts`), новая роль добавляется без миграции. `created_at` и
`updated_at` ставит Nest: у таблицы нет значений по умолчанию.

## Правила записи

Правила держит `ProviderImageService`, файловые операции — `ProviderImageStorage`.

- Формат определяется по первым байтам файла: PNG или JPG. Расширение имени и заголовок
  браузера в расчёт не идут.
- Размер файла не больше 2 МБ, сторона не больше 6000 пикселей (react-pdf разворачивает
  картинку в память целиком). Размеры читает sharp. Лимиты проверяются на загруженном файле.
- Перед записью картинка перекодируется через sharp в простой вид, который react-pdf точно
  рисует (`normalizeProviderImage`): PNG — 8 бит на канал, sRGB, RGBA, без чересстрочности и
  палитры (16-битные и серые PNG приводятся к нему же); JPEG — sRGB (CMYK переводится), не
  прогрессивный, цветность 4:4:4, качество 90. Поворот из EXIF применяется к пикселям, метаданные
  не сохраняются. Формат остаётся прежним (PNG или JPEG). В `format`, `width`, `height`, `size`
  записи идут значения перекодированного файла.
- Файл пишется через временный файл и `rename`: недописанной картинки под своим именем нет.
- Замена: сначала записывается новый файл и запись, затем удаляется прежний файл. Сбой записи
  в базу убирает новый файл, прежний остаётся. Id записи при замене меняется вместе с файлом.
- Удаление терпимо к отсутствию файла: нет файла на диске — запись всё равно удаляется.
- Загрузки в одну пару «реквизиты и роль» идут по очереди.
- В базе лежит путь без корня хранилища; путь, выводящий за `storage/app`, отвергается.

Ошибки пользователя — 400 с текстом по-русски (`provider-image.messages.ts`): неизвестная
роль, файл не передан, чужой формат, файл не читается как картинка, превышены размер или
пиксели. Нет реквизитов или картинки — 404.

## Где используется

Модуль `ProviderImageModule` без контроллеров. Подключают:

- админка: `ProviderAdminModule` регистрирует `ProviderImageAdminController`
  (`admin/portal/provider/rq/:rqId/images`, список, загрузка и замена, файл для превью,
  удаление; описание в Swagger);
- konstructor: `OfferPdfModule`. Сервис модели PDF-КП читает картинки реквизитов поставщика
  через `ProviderImageService.loadContents`. Логотип читается всегда, печать и подпись
  руководителя — при включённом «с печатями и подписями». Подпись бухгалтера хранится и в КП пока
  не печатается. Word этим модулем пока не читается.

## Прод: код раньше миграции

Код выкладывается раньше таблицы. Чтение картинок при сборке PDF переживает отсутствие таблицы:
ошибка пишется в лог одной строкой на документ, документ собирается без картинок (в том числе без
логотипа). Админ-ручки до миграции отвечают ошибкой базы.

## Временный перенос из легаси

Печати, подписи и логотипы реквизитов лежат у легаси (Laravel) в таблице `files` и в папке
`clients` хранилища. Временная ручка переносит их в `provider_images`. Весь код переноса
собран в `legacy-import/` и удаляется одним куском, когда перенос закончен.

**Ручка:** `POST /api/admin/portal/provider/images/legacy-import?dryRun=true|false`
(multipart, поле `files`, до 100 файлов, до 10 МБ каждый; ограничение 2 МБ и 6000 пикселей
на саму картинку остаётся за `ProviderImageService`). Без `dryRun` выполняется проверка.

**Что делает.**

1. Имя каждого файла несёт относительный путь внутри папки `clients`
   (`clients/<домен>/rq/<rqId>/<роль>/<имя>.png`): браузер присылает его из `webkitRelativePath`,
   сервер оставляет путь в имени (`preservePath` у multer). Всё, что стоит перед `clients/`,
   отбрасывается, обратные слэши заменяются прямыми.
2. Путь сопоставляется с `files.path` точно. Запись относится к реквизитам, если
   `entity_type = 'App\Models\Rq'`, `parent = 'rq'`, `entity_id = rqs.id`.
   Если клиент прислал имя без корня `clients/` (только название файла или часть пути),
   запись ищется по хвосту пути `files.path` и принимается, когда подходит ровно одна. Иначе
   файл попадает в отчёт как `skipped` с пояснением.
3. Для реквизитов, к которым относятся загруженные файлы, правила легаси выбирают «текущую»
   картинку каждой роли (`lib/pick-legacy-provider-images.ts`):
   `logo` и `stamp` — запись с наименьшим id; `signature_director` — наибольший id среди
   `parent_type = 'signature'` с `code`, отличным от `signature_accountant`;
   `signature_accountant` — наибольший id среди `signature` с `code = 'signature_accountant'`.
   Остальное (`qr`, вторые и далее логотипы и печати, прежние подписи, записи с
   `parent_type = 'signature_accountant'`, неизвестные типы) получает `skipped` и пояснение.
4. Картинки пишет `ProviderImageService.put` с `legacyFileId`: перекодирование sharp и лимиты
   те же, что у загрузки из админки. Существующие картинки не перезаписываются.

**Итог по каждой записи `files`:** `imported` (перенесено), `would-import` (будет перенесено,
режим проверки), `exists` (у реквизитов уже есть другая картинка этой роли), `already` (эта
запись уже перенесена, повторный запуск копий не плодит), `no-file` (файл записи не загружен),
`skipped` (запись не переносится), `error` (ошибка записи, текст в `message`). В отчёт
попадают все записи `files` затронутых реквизитов и загруженные файлы без записи
(`role: null`, `legacyFileId: 0`, `rqId: 0`).

**Порядок для владельца.**

1. Выложить код и убедиться, что миграция `provider_images` применена.
2. В админке выбрать папку `clients` (копия из хранилища легаси) и нажать «Проверить»
   (`dryRun=true`): ничего не записывается. Просмотреть отчёт: `no-file`, `error` и
   неожиданные `exists` разобрать до переноса.
3. Нажать «Перенести» (`dryRun=false`). Повторный запуск безопасен: перенесённое отвечает
   `already`, исправленные файлы переносятся.
4. Проверить картинки в карточках реквизитов, затем удалить временный код.

**Как удалить.**

1. Папка `provider-image/legacy-import/` целиком.
2. `provider/provider-image-legacy-import.admin.controller.ts` и
   `provider/provider-image-legacy-import.admin.http.spec.ts`.
3. В `provider/provider.admin.module.ts`: импорт `ProviderImageLegacyImportModule`, строка в
   `imports`, импорт контроллера и строка в `controllers`, абзац про перенос в комментарии.
4. Не обязательно, но можно: необязательный параметр `options` в `ProviderImageService.put` и
   экспорт `recodeLatin1Name` в `lib/provider-image-file.util.ts` останутся безвредными, а тест
   «перенос из легаси: legacyFileId» в `__tests__/provider-image.service.spec.ts` удаляется
   вместе с параметром. Колонка `provider_images.legacy_file_id` остаётся: она хранит, откуда
   перенесена картинка.

## Тесты

`__tests__/`: формат и размеры, перекодирование (чересстрочный и 16-битный PNG, CMYK и
прогрессивный JPEG, поворот EXIF), хранилище, сервис на настоящих временных файлах, Prisma-репозиторий
на моках. Ручки проверяет `provider/provider-image.admin.http.spec.ts` (multipart через multer).
Картинки тесты рисуют через sharp, файлов картинок в git нет. Перенос из легаси проверяют
`legacy-import/__tests__/` (выбор записей, пути, сервис на репозиториях в памяти, Prisma-репозиторий
на моках) и `provider/provider-image-legacy-import.admin.http.spec.ts` (multipart, пути в именах).
